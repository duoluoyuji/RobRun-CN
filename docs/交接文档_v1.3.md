## 二、安装/还原机制（v1.3 起，重要变更）

旧方案（v1.0–v1.2）：改写游戏目录的 aa\catalog.bin 做重定向，或直接覆盖原版资源包。
**这两个做法在 11-20 版本都会出问题**：
- 改 catalog.bin → 触发 E-0124（新版 catalog 版本化 + hash 校验）
- 覆盖原版资源包 → 反作弊判定「未知的文件版本」，弹窗拦截

v1.3 采用现行方案（与社区成熟补丁一致）：

| 步骤 | 动作 | 是否改动游戏原版文件 |
| :--- | :--- | :--- |
| 1 | 把 8 个汉化资源包以 `*_zh0.bundle` **新文件名**放进 `aa\StandaloneWindows64` | 否（只新增文件） |
| 2 | 把官方 `aa\catalog.bin` **复制**到用户缓存目录，在副本里把 8 个包名等长改成 `_zh0` | 否（只改缓存副本） |
| 3 | 同时写入缓存的 `catalog.hash` | 否 |
| 4 | 还原：删除 8 个 `*_zh0.bundle`，把缓存目录整体改名备份 | 否 |

用户缓存目录：`%USERPROFILE%\AppData\LocalLow\Kefir\ROB RUN\com.unity.addressables`

**为什么必须改写缓存而不是游戏目录**：游戏以 `catalog.hash` 判断缓存是否有效；只换 hash 不换 bin（游戏更新器的缺陷）会导致读旧清单 → 找不到新资源 → 报 E-0124。

## 三、E-0124 与「旧缓存」问题（务必了解）

现象：启动报 `Failed to load game data`、错误码 E-0124，进不去游戏。
真实原因：缓存里的 `catalog_<版本>.bin` 是旧的，但 `.hash` 已被游戏更新成新值，Addressables 认为缓存有效 → 加载旧清单 → `InvalidKeyException`。**与网络无关**，报错文案是写死的。

处理：
- 工具**启动自检**：把缓存里的 `_zh0` 反解成 `_all` 后与安装目录 `catalog.bin` 逐字节比对；不一致 → 把缓存目录改名备份（`.bak_时间戳`），若已装汉化则自动重建指向汉化的缓存（中文不掉）。
- 手动兜底：包内「5-修复启动报错-清理缓存.bat」（等价于上述操作）。
- 判定不了（无 catalog.bin / 无缓存 / 无 catalog_*.bin）→ 什么都不做，避免误伤。

## 五、日常维护流程（游戏更新后）

1. **更新官方基线**：从游戏目录复制 8 个官方 bundle + catalog.bin/hash 到 `_v2\assets\official-<日期>`。
2. **导出新文本**：用当前官方语言表导出 `strings_en.csv`，与上一版做 ID diff，找出新增/改动条目。
3. **补译**：写进 `_v2\data\已译补丁.csv` 与 `已译补丁_繁體.csv`（两边都要，繁体可先经简繁转换再人工改）。
4. **查缺字**：若新增译文用到字库没有的汉字，跑 `patch_perfect_fonts_tw.py`（或按同写法处理简体）；**参数不要改**（point/pad 取自字体资产、4x 超采样、0.88 横向比例）。
5. **打包**：
   `python build_pack.py <译文CSV> <输出目录> <官方bundle目录> <字库inbuild> <locales bundle>`
6. **过闸门**：`python check_release.py <词典CSV> <官方表CSV> <字库inbuild> <包目录>`
   - 六项必须全 PASS：词条数=官方、参数不越界、plural 段数一致、富文本标签不缺、无批注残留、字库 0 缺字。
7. **组包**：`_v2\tools\build_suite_v2.ps1`（编译 EXE、组装目录、写 SHA256 清单、压缩）。
8. **自测**：还原 → 装简 → 装繁 → 还原，四个动作验证文件状态与游戏内文本。
9. **发布**：更新仓库 `src/`、`tools/` 词典、`version.json`、README；打 tag；建 Release 上传 zip；**发布说明只写“改了什么”，不写实现细节**。
